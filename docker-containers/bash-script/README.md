# 🐳 Docker Container Security Audit

Набор bash-скриптов для автоматизированного аудита безопасности (Hardening Check) работающих Docker-контейнеров. 

Инструмент последовательно подключается к каждому контейнеру через `docker exec`, выполняет набор проверок по чек-листу и формирует единый текстовый отчет о состоянии системы безопасности.

---

## ⚙️ Как это работает (Архитектура)

Скрипт разделен на две логические части:

1. **`audit_all.sh` (Движок):** 
   * Управляет списком контейнеров.
   * Создает файл отчета в папке `./audit_reports/`.
   * Содержит функцию `check()`, которая выполняет роль «форматтера». Она принимает название раздела, описание проверки и саму bash-команду, а затем выполняет эту команду внутри каждого контейнера через `docker exec` и записывает результат в отчет с красивыми разделителями.
   * Вызывает `checklist.sh` для старта проверок.

2. **`checklist.sh` (База знаний):** 
   * Это сам чек-лист. Он не содержит логики выполнения, а просто вызывает функцию `check` нужное количество раз с конкретными командами.
   * Проверки сгруппированы по разделам с помощью комментариев.

---

## 📋 Что именно проверяется (Функционал)

Чек-лист содержит более 60 проверок, разбитых на логические блоки:

*   **Учётные записи:** Поиск общих учетных записей (admin, user, test), дубликатов UID, проверка сервисных УЗ на наличие интерактивного shell, запрет прямого входа под `root`.
*   **Парольная политика:** Аудит `/etc/security/pwquality.conf`, проверка подключения модуля `pam_pwquality`, поиск пустых паролей, проверка алгоритма хеширования (должен быть SHA-512), сроки действия паролей (`chage`), проверка `login.defs`.
*   **Логирование:** Статус `rsyslog` и `systemd-journald`, права на файлы логов, наличие событий `sudo` и `sshd`, настройки ротации логов, проверка перенаправления логов на внешний SIEM.
*   **Сеть и порты:** Список слушающих портов (`ss`, `netstat`), правила файрволов (`ufw`, `firewalld`, `iptables`), политики по умолчанию (deny by default).
*   **Сервисы и обновления:** Версии ОС и ядра, наличие security-обновлений (apt/dnf), автообновления, проверка защиты сетевого стека через `sysctl` (syncookies, redirects), поиск world-writable файлов.
*   **Изоляция сервисов:** Проверка того, под какими пользователями (root или нет) работают процессы. Детальный аудит таких сервисов, как Nginx, Samba, CoreDNS, rsyslog, FTP.
*   **Веб-сервисы (Nginx):** Проверка версии, отключение `server_tokens` (скрытие версии), параметры SSL/TLS, настройки таймаутов и Security Headers.
*   **DNS-сервис:** Проверка статуса, конфигурации, зон, а также защита от «открытого резолвера» (проверка параметра `recursion` и `allow-query`).
*   **Файловый сервер:** Права доступа к каталогам (например, `/srv/files`).
*   **Именование:** Проверка длины `hostname` (не более 15 символов).

## 🚀 Инструкция по запуску

### 1. Требования
*   Хост-система на базе Linux.
*   Установленный Docker.
*   Права `root` (или `sudo`), так как для чтения некоторых файлов внутри контейнеров (например, `/etc/shadow`) требуются повышенные привилегии.

### 2. Настройка
Откройте файл `audit_all.sh` и впишите названия ваших контейнеров в массив `CONTAINERS`:
```bash
CONTAINERS=(
  "nginx-proxy"
  "backend-app"
  "postgres-db"
)
